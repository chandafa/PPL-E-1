# API E-1 (Pencatatan e-Faktur dan pajak proyek) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Membangun API E-1 (11 operasi API-KE01-01..11) di Laravel + PostgreSQL yang persis mengikuti `openapi.yaml` Pertemuan 3.

**Architecture:** Laravel stateless API (`/api/v1`), middleware autentikasi JWT F-1, layanan domain (faktur, rekap, pembayaran, riwayat) di `app/Services`, adapter D-2 lewat antarmuka `InvoiceProvider` (mock dahulu), ekstraksi PDF lewat `EFakturPdfParser`. Semua respons dibungkus amplop `{code,message,data[,errorCode]}`.

**Tech Stack:** PHP 8.4, Laravel 13, PostgreSQL 18 (lokal; skema diuji ringkas di 16), PHPUnit 12, firebase/php-jwt, smalot/pdfparser, maatwebsite/excel, barryvdh/laravel-dompdf, opis/json-schema (uji kontrak).

**Spec:** `../../../../Pertemuan3/openapi.yaml` (+ `examples/`), `../../../../Pertemuan2/03_ERD_Skema_Data_Awal_E-1.sql`, `../../../../_catatan_claude/KONTEKS_PEMBANGUNAN_API_LARAVEL.md`, `../../../../_catatan_claude/ANALISIS_PROYEK_E-1.md`.

## Global Constraints

- 11 operasi, ID stabil `API-KE01-01..11`; path dan operationId persis seperti `openapi.yaml`.
- Amplop sukses `{"code":"200","message":"...","data":{...}}`; gagal `{"code":"4xx","message":"...","data":null,"errorCode":"<ENUM>"}`; `code` sama dengan status HTTP (string). Ekspor (API-09) berkas biner tanpa amplop.
- Sukses selalu HTTP 200 (juga POST), kecuali kesalahan.
- Nominal decimal(18,2) selalu **string** (`^-?[0-9]{1,16}\.[0-9]{2}$`); tanggal `YYYY-MM-DD`; waktu RFC 3339 UTC `...Z`; masa pajak `YYYY-MM`.
- ID E-1 = UUID v7. Kolom database snake_case; JSON camelCase.
- Auth: `Authorization: Bearer <JWT F-1>`; token tidak ada/tidak sah → 401 `UNAUTHORIZED`; peran selain Admin/CEO/COO → 403 `FORBIDDEN`.
- Berkas PDF maksimum 5 MB; hanya PDF (cek tipe dan header `%PDF-`).
- 1 invoice : 1 faktur aktif (Q-04); NSFP unik; tidak ada hard delete; riwayat append-only (Q-05..Q-07).
- Rekap hanya menghitung faktur aktif: bukan CANCELLED dan belum diganti (Q-13).
- Faktur masukan di luar cakupan; field `type` dan `vendorName` tetap ada sesuai file 03 (keputusan pengguna: kontrak menyesuaikan).
- Tanpa integrasi DJP; E-1 tidak menerbitkan e-Faktur.

## Review Focus

- PATCH multipart (API-11): PHP tidak mengurai `multipart/form-data` untuk PATCH; harus diuji lewat server HTTP sungguhan, bukan hanya klien uji. Harapan: `ntpn` dan berkas terbaca.
- Dua permintaan simultan untuk invoice yang sama: hanya satu faktur aktif yang boleh lahir (409 untuk yang lain).
- Faktur pengganti dari faktur yang sudah dibatalkan/sudah diganti: ditolak 409, bukan membuat dua faktur aktif.
- Koreksi `taxPeriod`: rekap periode lama dan baru keduanya dihitung ulang.
- Jumlah setor kurang dari PPN: `paymentDifference` negatif dan tetap tersimpan (bukan ditolak).
- Periode tanpa faktur: rekap dan ringkasan mengembalikan nol (200), bukan 404 atau angka karangan.
- Token kedaluwarsa, `aud`/`iss` salah, atau tanda tangan salah → 401, bukan 403/500.
- PDF bukan e-Faktur (PDF sah tetapi tanpa label pajak): 400 `EXTRACTION_FAILED`, tidak ada catatan parsial.

## Tasks

### Task 1: Fondasi (amplop, error, konfigurasi, auth)
**Files:** `config/e1.php`, `app/Exceptions/ApiException.php`, `app/Support/ApiResponse.php`, `app/Http/Middleware/AuthenticateF1Token.php`, `bootstrap/app.php`, `routes/api.php`, `app/Console/Commands/IssueDevToken.php`; Test: `tests/Feature/AuthTest.php`, `tests/Unit/F1TokenVerifierTest.php`.
**Produces:** `ApiException::make(int $status, string $errorCode, string $message)`; `ApiResponse::ok(mixed $data, string $message): JsonResponse`; request attribute `f1.identity` (`F1Identity{akunId, role}`); artisan `f1:token {akunId} {role}`.
- Uji: tanpa token → 401 UNAUTHORIZED amplop; token kedaluwarsa/aud salah → 401; peran CTO → 403 FORBIDDEN; Admin lolos; kesalahan tidak terduga → 500 amplop tanpa jejak tumpukan.
